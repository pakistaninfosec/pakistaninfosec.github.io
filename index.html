About This Platform

Pakistan's First Free Cybersecurity Threat Intelligence Platform

InfoSec Pakistan was built with a single mission: to make enterprise-grade cybersecurity threat intelligence accessible to every Pakistani organization, CISO, security analyst, and IT professional — completely free, no login required.

🛡

What InfoSec Pakistan Does

InfoSec Pakistan is a fully automated threat intelligence platform that aggregates, processes, and delivers cybersecurity data from the world's most trusted sources — every 30 minutes, around the clock. Our automated pipeline pulls vulnerability data from CISA's Known Exploited Vulnerabilities (KEV) catalog, the National Vulnerability Database (NVD/NIST), Exploit-DB, Pakistan CERT (pkcert.gov.pk), and NCCS Pakistan (nccs.pk).

Each run collects hundreds of threat entries, deduplicates them, scores them by severity, flags Pakistan-specific advisories, and generates an AI-powered executive summary using Meta's LLaMA model via Groq — delivering a concise, actionable digest that a CISO can read in under two minutes.

Unlike commercial threat intelligence platforms that charge thousands of dollars per year, InfoSec Pakistan provides this intelligence layer entirely free. Our goal is to raise the cybersecurity baseline across Pakistan's public sector, banking industry, telecom sector, and academic institutions.

🎯

Why Threat Intelligence Matters for Pakistan

Pakistan faces a rapidly escalating cyber threat landscape. Government portals, banking infrastructure, telecom networks, and critical systems are increasingly targeted by nation-state actors, ransomware groups, and opportunistic attackers. According to Pakistan CERT and NCCS advisories, Pakistani organizations regularly face active exploitation of vulnerabilities that have known patches available — meaning many breaches are preventable.

The problem is not a lack of threat data — it exists in abundance across dozens of global sources. The problem is access and translation. Most Pakistani security teams lack the budget for commercial threat feeds, and manually monitoring CISA, NVD, Exploit-DB, and Pakistan CERT simultaneously is not practical. InfoSec Pakistan solves this by aggregating everything into one dashboard, updated every 30 minutes, with Pakistan-specific alerts clearly flagged with a 🇵🇰 badge.

When a zero-day is discovered in Fortinet, Cisco, or Microsoft products — products widely deployed across Pakistan's enterprise and government infrastructure — you need to know within hours, not days. That is exactly what this platform delivers.

Our Analysis Methodology

InfoSec Pakistan follows a rigorous, transparent methodology to ensure data quality and relevance. Here is exactly how our pipeline works:

Step 1
Data Collection
Every 30 minutes, our GitHub Actions pipeline runs an automated Python scraper that queries five verified threat intelligence sources via their official APIs and RSS feeds: CISA KEV JSON feed, NVD REST API (last 24 hours), Exploit-DB RSS, Pakistan CERT advisory page, and NCCS Pakistan blog. Only entries published within the relevant time window are collected — ensuring the dashboard reflects current threats, not historical archives.
Step 2
Normalization & Deduplication
Raw data from different sources uses different schemas and identifiers. Our pipeline normalizes every entry into a consistent format — CVE ID, description, severity score, affected vendor/product, publication date, source, and Pakistan relevance flag. SHA-256 hashing ensures duplicate entries from multiple sources are merged rather than repeated.
Step 3
Severity Scoring & Prioritization
Every threat entry is scored using CVSS severity ratings (Critical, High, Medium, Low). Pakistan-specific advisories from PKCERT and NCCS are automatically flagged with the 🇵🇰 indicator and surfaced at the top of the threat list. Actively exploited vulnerabilities from CISA KEV are tagged separately as they represent the highest-priority patching targets.
Step 4
AI-Powered Executive Summary
After data collection and normalization, the top critical and Pakistan-specific threats are passed to Meta's LLaMA 3.3 70B model (via Groq API) with a carefully engineered prompt that instructs the model to write a concise, specific, actionable 3-sentence executive summary. The prompt includes actual CVE IDs, affected vendor names, and Pakistan alert counts — ensuring the summary is specific to today's threats, not generic boilerplate.
Step 5
Publication & Delivery
The processed threat data is saved as a structured JSON file (data/threats.json) and committed to our GitHub repository. GitHub Pages serves this file publicly, and the dashboard fetches it in real-time on every page load with cache-busting. The entire pipeline — from data collection to website update — completes in under 60 seconds.
